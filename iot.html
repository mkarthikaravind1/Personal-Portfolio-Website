Hardware & Embedded Systems

IoT & Embedded Works

A collection of ESP32-based IoT experiments and real-time embedded systems built during ProtoSem 1.18 — spanning sensor automation, cloud/voice control, and FreeRTOS task design.

IoT Experiment 1

Blinking an LED on ESP32

The first experiment in the IoT progression — programming the ESP32 to blink an onboard/external LED, confirming the board setup, GPIO control, and toolchain before moving on to networked control.

IoT Experiment 2

Bulb Control via Locally Hosted Website

Controlling a bulb's on/off state through a locally hosted website using Arduino — the ESP32 serves a simple web page on the local network, and toggling a button on that page switches the bulb.

Demo Video

IoT Experiment 3

Bulb Control via Google Voice Assistant

Extending Experiment 2's website with voice control — the same bulb can now be switched on or off through a Google Voice Assistant command routed to the local web interface.

Demo Video

IoT Experiment 4

Bulb Control via Firebase-Connected Website

Moving from local to cloud control — the bulb is now controlled through a website connected to Firebase, allowing the ESP32 to read state changes from the cloud database from anywhere.

Demo Video

IoT Experiment 5

Bulb Automation via LDR Sensor

The final experiment closes the loop with autonomous sensing — an LDR (light-dependent resistor) automatically switches the bulb on or off based on ambient light levels, with no manual or remote trigger needed.

Project

FreeRTOS Temperature Alert System

A multi-task FreeRTOS system on the ESP32 using a DHT11 sensor. The system runs four independent tasks: a Temperature Task sampling every 200 ms that sends a notification when the reading hits 30°C or above, an LED Task that stays blocked until notified and then pulses for 100 ms, a Button Task that acknowledges the alert on a single press, and a UART Task that independently logs temperature, threshold, and alert status. Inter-task communication uses FreeRTOS task notifications exclusively — no shared variables — meeting a max alert latency of 100 ms and jitter of ±5 ms.
